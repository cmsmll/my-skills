# task-optimizer — 任务提示词优化与执行

用户执行 `Task.md` / `task.md`（或其它任务文件）时，不要直接埋头执行原始描述——先优化、再确认、后执行。流程：**读取任务文件 → 同模型子代理优化提示词 → ask 询问改进点 → 确认后主 agent 真正执行**。

## 执行步骤

### ① 读取任务文件

1. 用 `read` 读取用户指定的任务文件（默认 `task.md`；用户给了其它路径/文件名则以用户给的为准）。
2. 文件不存在或内容为空 → 停下，告知用户文件问题并请其补充任务内容，不继续后续步骤。
3. 通读任务内容，记下核心目标、约束与交付物，供传给子代理。

### ② 开同模型子代理优化提示词

1. 用 `task` 工具开**一个**子代理执行优化，**不指定 `agent` 类型**（省略即默认 worker，与主会话同模型）。⛔ 不要用 `scout`——scout 用更快但不同的模型，不满足「同模型」要求。
2. 子代理的任务描述中必须**显式给出任务文件路径**（子代理看不到会话历史，不给路径它就无从下手），要求它：
   - 先用 `read` 读取任务文件全文；
   - 把原始任务改写成**清晰、无歧义、可直接执行**的提示词，至少包含：目标、范围、执行步骤、约束、验收标准；
   - 保留原任务的全部意图，不擅自增删需求；
   - **只输出优化后的提示词**（作为最终输出返回），不要执行任务本身。
3. 子代理返回后，主 agent 拿到优化后的提示词全文。

### ③ ask 询问改进点

1. 先向用户简要展示优化结果要点：目标、关键步骤、验收标准（一两行摘要即可，不必全文粘贴）。
2. 用 `ask` 弹出交互对话框确认：

- `i`（intent）：如「确认优化后任务提示词」；
- `question`：如「优化后的任务提示词已生成（见上方摘要）。还有哪里需要改进的吗？」
- `options`：
  - 「无需改进，直接执行任务」——`description`：按优化后的提示词开始真正执行（推荐）；
  - 「需要改进」——`description`：在 Other 中填写具体改进点；
- `recommended`：0（无需改进项）。

### ④ 合并改进点（如用户提出）

1. 用户提出改进点 → 合并进优化后的提示词：
   - 改动点少、不影响整体结构 → 主 agent 直接修订；
   - 改动大、需要整体重写 → 再开一轮同模型子代理（复用 ② 的写法，把原提示词与改进点一并传入），或再次 ask 确认关键分歧。
2. 合并后**再次确认**用户是否还有改进点（可再走一次 ③）；用户明确「可以了/执行」后才进入 ⑤。不要问完就擅自执行。

### ⑤ 主 agent 真正执行任务

1. 用户确认无需改进后，由**主 agent 本人**按优化后的提示词执行任务——优化环节的子代理已完成使命，不再参与执行。
2. 执行时遵循提示词中的步骤与验收标准，完成后按验收标准逐项汇报结果。

## 注意事项

- **子代理只优化、不执行**：优化是子代理的事，执行是主 agent 的事，两者不混。
- **路径必须传给子代理**：子代理看不到会话历史，任务文件路径、以及改进轮次中的既有提示词内容，都要写进子代理的任务描述。
- **「同模型」= 不指定 agent 类型**：省略 `agent` 字段用默认 worker；指定 `scout` 会换用不同模型。
- **确认后才执行**：ask 只是收集意见，用户明确「无需改进/可以执行」前，不开始 ⑤。
- **不擅自改需求**：优化只做澄清、补全、结构化，不新增或删减原任务意图；与原意冲突的改动需先 ask 用户。
