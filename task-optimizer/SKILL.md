# task-optimizer — 任务提示词优化与执行

用户执行 `Task.md` / `task.md`（或其它任务文件）时，不要直接埋头执行原始描述——先优化、再确认、后执行。流程：**读取任务文件 → 同模型子代理优化提示词并提出疑问 → ask 多问题表格确认（问题1..N｜其他问题｜确认提交）→ 确认后主 agent 真正执行**。

## 执行步骤

### ① 读取任务文件

1. 用 `read` 读取用户指定的任务文件（默认 `task.md`；用户给了其它路径/文件名则以用户给的为准）。
2. 文件不存在或内容为空 → 停下，告知用户文件问题并请其补充任务内容，不继续后续步骤。
3. 通读任务内容，记下核心目标、约束与交付物，供传给子代理。

### ② 开同模型子代理优化提示词并提出疑问

1. 用 `task` 工具开**一个**子代理执行优化，**不指定 `agent` 类型**（省略即默认 worker，与主会话同模型）。⛔ 不要用 `scout`——scout 用更快但不同的模型，不满足「同模型」要求。
2. 子代理的任务描述中必须**显式给出任务文件路径**（子代理看不到会话历史，不给路径它就无从下手），要求它：
   - 先用 `read` 读取任务文件全文；
   - 把原始任务改写成**清晰、无歧义、可直接执行**的提示词，至少包含：目标、范围、执行步骤、约束、验收标准；
   - **提出疑问**：找出原任务中的模糊点、缺失环节、歧义表述，整理成**疑问清单**，每个疑问附 2–5 个可选答案选项，供主 agent 转成 ask 选项；
   - 保留原任务的全部意图，不擅自增删需求；
   - **只输出优化后的提示词与疑问清单**（作为最终输出返回），不要执行任务本身。
3. 子代理返回后，主 agent 拿到优化后的提示词全文与疑问清单。

### ③ ask 多问题表格确认

1. 先向用户简要展示优化结果要点：目标、关键步骤、验收标准（一两行摘要即可，不必全文粘贴）。
2. 用 `ask` 一次弹出**多个问题**（表格化表单），交互形态对齐「问题1｜问题2｜问题3｜…｜其他问题｜确认提交」：
   - **问题1（执行方式）**：「确认并覆盖」——确认执行并把优化后的提示词覆盖写入原任务文件（推荐）；「确认不覆盖」——确认执行但不改动原文件；
   - **问题2..N（疑问清单）**：来自子代理的疑问清单，每个疑问作为一个问题，附 2–5 个选项并标注 `recommended`（推荐项）；
   - **其他问题**：每个问题自带 Other 自由输入入口，用户可补充任何疑问或改进点；
   - **确认提交**：用户提交表单即视为本轮确认，提交后才进入下一步。
3. `questions` 数组一次传入全部问题，不逐个单独提问；`i`（intent）如「确认优化后任务提示词」。

### ④ 合并改进点（如用户提出）

1. 用户通过任何问题的选项或 Other 提出改进点 → 合并进优化后的提示词：
   - 改动点少、不影响整体结构 → 主 agent 直接修订；
   - 改动大、需要整体重写 → 再开一轮同模型子代理（复用 ② 的写法，把原提示词与改进点一并传入），或再次 ask 确认关键分歧。
2. 合并后**再次走 ③ 的 ask 多问题表格确认**（可把「还有哪里需要改进」作为新问题列入，选项「无需改进／需要改进」）；用户提交「确认提交」后才进入 ⑤。不要问完就擅自执行。

### ⑤ 主 agent 真正执行任务

1. 用户确认后，若选择「确认并覆盖」：先用 `write` 把优化后的提示词全文覆盖写入原任务文件（如 `task.md`），让优化结果沉淀到任务文件本身；若选择「确认不覆盖」：不写文件，优化结果仅本次会话使用。
2. 由**主 agent 本人**按优化后的提示词执行任务——优化环节的子代理已完成使命，不再参与执行。
3. 执行时遵循提示词中的步骤与验收标准，完成后按验收标准逐项汇报结果。

## 注意事项

- **子代理只优化、不执行**：优化与提问是子代理的事，执行是主 agent 的事，两者不混。
- **路径必须传给子代理**：子代理看不到会话历史，任务文件路径、以及改进轮次中的既有提示词内容，都要写进子代理的任务描述。
- **「同模型」= 不指定 agent 类型**：省略 `agent` 字段用默认 worker；指定 `scout` 会换用不同模型。
- **ask 用多问题表格，不逐个单独提问**：一次表单包含问题1..N、其他问题入口（每个问题自带 Other）与确认提交；用户提交表单即确认。
- **「确认并覆盖」会改写原任务文件**：原内容被优化后的提示词替换，属用户确认过的改写；「确认不覆盖」不改任何文件。
- **确认提交后才执行**：ask 只是收集意见，用户提交表单（确认提交）前，不开始 ⑤。
- **不擅自改需求**：优化只做澄清、补全、结构化，不新增或删减原任务意图；与原意冲突的改动需先 ask 用户。
